# ADR-0001 — Index Numbers Are Reserved for Confirmed Decisions

**Status:** PROPOSED (meta-ADR — numbering convention)

**Date:** 2026-09-13 · **Owner:** Platform owner

**Context:** Phase-1B approvals confirmed four architecture decisions simultaneously.
The Phase-1 report recommended ADR numbering (ADR-001: INDEXED/RELATIVE; ADR-002:
oracle; ADR-003: platform language; ADR-004: verdict vocabulary) but those numbers were
assigned in roadmap order, not importance order.

**Decision:** ADR numbers are permanent once assigned. The four confirmed decisions take
ADR-0001..ADR-0004 in the order the owner approved them (PD-01..PD-07 mapped below).
Meta-conventions may live in ADR-0000.

**Consequences:** Future ADRs continue from ADR-0005. A rejected decision still consumes
its number (recorded as REJECTED) so references remain stable.

# ADR-0001 — Authoritative COBOL Oracle (V1)

**Status:** **ACCEPTED (CONFIRMED)**

**Date:** 2026-09-13 · **Owner:** Platform owner
**Authority:** Phase-1B owner approval, PD-01 — verbatim record in
[PHASE1B_OWNER_APPROVALS.md](PHASE1B_OWNER_APPROVALS.md). Supersedes open DR-08.

## Context

The validation platform needs an authoritative behavioral reference for the original
COBOL. Forensic evidence (Phase-1 report E1): GnuCOBOL 3.1.2.0 + Open-COBOL-ESQL 1.4 is
the only oracle ever executed (85+ real differential runs; SHA-pinned Dockerfile
precedent). z/OS: no access evidence. Hercules/z390: predecessor scaffolding only.

## Decision

1. **V1 authoritative oracle = GnuCOBOL 3.1.2.0 + Open-COBOL-ESQL 1.4**, executed in a
   Docker image **pinned by digest** (never a mutable tag).
2. **Every verdict MUST explicitly include the oracle identity scope** — verdicts state
   "equivalent to GnuCOBOL 3.1.2.0 (image digest …) under the declared environment."
3. **Never claim z/OS equivalence.** z/OS remains FUTURE (DR-27) unless explicitly
   decided otherwise.

## Consequences

- Oracle identity (adapter + image digest + compiler versions) is a mandatory verdict and
  evidence field.
- GnuCOBOL limitations (dialect coverage, ISAM≠VSAM physical semantics, no DB2 z/OS, no
  CICS, no JCL runtime) surface as explicit scope clauses, never hidden assumptions.
- ORACLE_CONTRACT.md is drafted against this decision.
- DR-08 → CONFIRMED; DR-24 (GnuCOBOL first adapter) confirmed by consequence.

# ADR-0002 — INDEXED/RELATIVE Representation Strategy

**Status:** **ACCEPTED (CONFIRMED)**

**Date:** 2026-09-13 · **Owner:** Platform owner
**Authority:** Phase-1B approval, PD-02.

## Context

Predecessor's only confirmed live false-PASS: substring containment compared a binary
8,192-byte KSDS container against a 26-byte text dump and passed (7/10 adversarial cases
wrongly green). No extraction mechanism existed. Formats now decoded (E2/E3):
RELATIVE = u64-LE length-prefix + record bytes per slot; INDEXED = page-structured
binary container.

## Decision

1. **V1 excludes INDEXED/RELATIVE content equivalence.** Workloads whose business
   contract requires file-content equivalence receive **`UNSUPPORTED`** for those
   artifacts — fail closed, stated in the verdict. (Stdout/file-status artifacts may still
   be compared per their own contracts.)
2. **V2 target = oracle-stage semantic dump/extraction:** a controlled dump program using
   the oracle's own `READ`/`START` semantics emits normalized logical records inside the
   oracle environment; the dump program is hash-pinned, evidence-bound, and
   mutation-tested before any verdict rests on it.
3. **Substring containment is permanently forbidden as a general equivalence strategy**
   — for INDEXED, RELATIVE, KSDS, RRDS, structured records, database state, or any
   semantic structured artifact, in all versions.

## Consequences

- No unproven file comparator ships in V1 — the false-PASS class is eliminated by
  exclusion, not by a rewritten-but-unproven comparator.
- ARTIFACT_CONTRACT_SPEC defines INDEXED/RELATIVE types as `UNSUPPORTED` in the V1
  contract registry.
- DR-09 → CONFIRMED.

# ADR-0003 — Platform Technology Stack

**Status:** **ACCEPTED (CONFIRMED)**

**Date:** 2026-09-13 · **Owner:** Platform owner
**Authority:** Phase-1B approval, PD-08.

## Context

Technology had to serve the three-layer architecture (DR-29, CONFIRMED): frontend /
backend / independently-executable engine. Evidence: the only proven execution-control
path for this domain was the predecessor's Python harness (E10); local toolchain
supports all recommended components (E9).

## Decision

| Layer | Technology | Constraint |
|---|---|---|
| Validation Engine | **Python 3.12** (version-pinned) | Independently executable — no HTTP/frontend/backend dependency; sole semantic trust boundary |
| Backend / Control Plane | **FastAPI** | Separate process/deployable; never semantic truth |
| Frontend | **React + TypeScript + Vite** | NEW project-owned design system |

**Mandatory:** the existing SystemaOps UI package is **NOT a dependency**; `@systemaops/ui`
must never be imported. Engine/backend may share a language while remaining strictly
separate processes; the backend must never import engine internals in a way that could
duplicate comparator logic.

## Consequences

- Python version discipline: 3.12 pinned; local 3.14 for tooling only.
- Engine-first implementation order becomes possible after contracts.
- DR-07 → CONFIRMED; DR-31 (frontend/backend implementation details) remains DEFERRED by
  owner.

# ADR-0004 — Verdict Vocabulary (Seven States)

**Status:** **ACCEPTED (CONFIRMED)**

**Date:** 2026-09-13 · **Owner:** Platform owner
**Authority:** Phase-1B approval, PD-07 (resolves DR-06 conflict; pairs with ADR-0005).

## Context

README documented a six-state working model; Phase-1 discussion proposed `ERROR` as a
seventh state for platform-internal failures, distinct from infrastructure-unavailable
and behavioral divergence. The predecessor conflated these three failure kinds with
fatal consequences (swallowed baseline exceptions became warnings).

## Decision

The verdict vocabulary is exactly seven states:

| State | Meaning |
|---|---|
| `VERIFIED` | Complete evidence; all mandatory invariants hold (the only certifiable state) |
| `PARTIAL` | Incomplete validation that does not qualify for V1 certification |
| `FAILED` | Behavioral divergence — the candidate demonstrably differs from the oracle |
| `UNPROVEN` | Insufficient evidence to determine equivalence either way |
| `UNAVAILABLE` | Required infrastructure/capability unavailable |
| `UNSUPPORTED` | Capability/artifact intentionally outside supported scope (fail-closed) |
| `ERROR` | Validator/platform processing failure — the validator itself failed to run or process inputs |

## Consequences

- DR-06 → CONFIRMED (seven states, `ERROR` included).
- UI/reports must render all seven distinctly; `ERROR` ≠ `UNAVAILABLE` ≠ `FAILED`; none
  of the non-VERIFIED states may ever render green.
- VERDICT_CONTRACT.md implements this vocabulary with the full prohibition set
  (SKIP→PASS, 0-checks→GREEN, etc. impossible by construction).
