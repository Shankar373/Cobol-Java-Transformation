# Scalability and Benchmark Plan

The 1 GiB and 10 GiB figures are engineering targets, not approved production quotas.

| Tier | Size | Purpose | Where |
|---|---|---|---|
| Small | about 1 MiB | functional correctness | every test run |
| Medium | about 100 MiB | throughput smoke | local focused run |
| Acceptance | 1 GiB | bounded memory, resume, determinism | local when 5 GiB disk free and 4 GiB RAM free; otherwise CI |
| Stress | 10 GiB | sustained streaming | only with 30 GiB free disk; otherwise recorded as not run |

Datasets are generated by a deterministic stream generator, never committed.

Measurements per run: bytes and records per second, peak RSS of the worker process,
wall time, output SHA-256. Pass criteria: peak RSS does not grow with dataset size
(compare Small vs Acceptance), repeated conversion gives an identical SHA-256, an
interrupted run resumed from a checkpoint matches an uninterrupted run, and a changed
source is refused on resume.

Results are written to `test-artifacts/benchmarks/` and copied into
`docs/operations/CERTIFICATION_EVIDENCE.md`. Numbers are never estimated.
