# Phase 5E — OpenSourceCOBOL4J Evaluation

**Date:** 2026-09-15
**Status:** COMPLETE

---

## Executive Summary

OpenSourceCOBOL4J successfully transforms the Claims Settlement COBOL source to Java, but the generated Java **requires `libcobj.jar`** (COBOL-specific runtime library). This means the generated application is **NOT standalone native Java** — it cannot run without the COBOL runtime dependency.

**Critical finding:** The current Claims COBOL source requires modification (`UPON STDERR` → `UPON SYSERR`) to compile with OpenSourceCOBOL4J.

3. **Classpath dependency** — Must include `libcobj.jar` in classpath

## 5A.13 Architectural Recommendation

### OPTION D: Do not adopt OpenSourceCOBOL4J because critical requirements are not met.

**Rationale:**

1. **Native Java requirement failed** — Generated Java requires `libcobj.jar` (LGPL-3.0 runtime)
2. **Docker complexity** — Must mount `libcobj.jar` and modify classpath
3. **License implications** — GPL-3.0 compiler + LGPL-3.0 runtime require legal review
4. **Distribution burden** — Must redistribute `libcobj.jar` with generated applications
5. **Current producer meets requirements** — Our Claims-specific generator produces standalone Java

### Alternative Consideration

If the "native Java" requirement were relaxed to allow runtime dependencies, OpenSourceCOBOL4J would be a stronger transformation producer for:
- INDEXED/RELATIVE file support
- Full COBOL language coverage
- Source-driven transformation proof
