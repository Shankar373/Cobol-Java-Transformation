## Gaps
1. **Silently wrong — mixed reference format.** Discovery returns `"mixed"` when a directive switches format mid-file (`cobol_text.py:112-115,146`), but the check lane maps every non-`free` format to `-fixed` (`compilers.py:387`) and the engine's detector can only return `free`/`fixed` from the *first* directive (`source_format.py:38-51`), applied once to the whole file (`cobol_parser.py:727-728`). A fixed→free file is read entirely as fixed (cols 73-80 and indicator column applied to free text).
2. **Silently wrong — Micro Focus sources.** `$SET SOURCEFORMAT` is honoured only by discovery (`cobol_text.py:21-22,116-124`); no `$SET`/`SOURCEFORMAT` exists under `engine/**`, so the directive line itself is sliced as fixed-format program text (`source_format.py:89,202,206`). Discovery then coerces `VARIABLE` to `fixed` with no refusal (`cobol_text.py:121-122`).
3. **Silently wrong — compiler and library cards reach the engine as COBOL.** Discovery strips `CBL`/`PROCESS`/`-INC`/`++INCLUDE`/`%INCLUDE` (`cobol_text.py:23-24,88,135`); no matching code exists under `engine/**`, so `CBL ARITH(EXTEND),DYNAM` or `++INCLUDE X` is text pasted into Area B (`source_format.py:89,202`). The options are recorded as facts (`scan_cobol.py:97-100`) but never applied to generation or to the oracle.
4. **Silently wrong — conditional compilation.** `>>IF`/`>>DEFINE`/`>>CALL` are recorded as directive facts (`cobol_text.py:125-127`, `scan_cobol.py:95-96`) and evaluated by neither side: the engine understands only `>>SOURCE` (no other `">>"` handling in `engine/**`), so both branches are parsed as live statements while GnuCOBOL compiles the evaluated one.
5. **Untested refusal — OO COBOL.** No `CLASS-ID`/`END CLASS` handling exists in `engine/transformation/*`; `_parse_program_id` falls back to `UNKNOWN` (`cobol_parser.py:1726-1732`) and `PARSE_ERROR` fires only when *no* structure was found (`cobol_parser.py:1711-1724`), so a class with `WORKING-STORAGE` is not obviously refused. Discovery does refuse it (`compilers.py:69-70`, `runtime_deps.py:146-147`); no fixture contains `CLASS-ID`.
6. **Silently wrong — `SCREEN SECTION`.** Ranked as an ordinary DATA DIVISION section and accepted when in order (`cobol_parser.py:1472-1475,1507-1523`); there is no `SCREEN` entry in `engine/transformation/semantic_capability.py` and no fixture, so screen-specific clauses are parsed as data-description clauses with undefined results.
7. **Dialect never reaches generation.** No `engine/**` module imports `enterprise.discovery` (grep), `dialect` does not appear under `api/**` (grep), and the producer manifest carries no dialect field (`engine/transformation/manifest.py:17-32`); the oracle compiles at GnuCOBOL default standard only (`docker_adapter.py:745`). Discovery's `-std=` selection (`compilers.py:80-81`) stays in the advisory syntax lane.
8. **The strongest dialect evidence is ignored.** The estate's own JCL names its compiler (`IGYCRCTL`, Micro Focus `ELAXF` → `compile-step` facts, `scan_jcl.py:174-180`), but `_signal` reads only `dialect-signal`, `compiler-option`, embedded-SQL/CICS/DLI, `directive` and `program-id` categories (`runtime_deps.py:135-148`), so `dialect_report` never sees it.
9. **Silently wrong — JCL conditionals.** Discovery records `IF/ELSE/ENDIF` and keeps processing both branches (`scan_jcl.py:128-129`); the engine states that "nothing evaluates them" (`engine/jcl/preprocess.py:20-21`), so a step that would never run is still expanded and modelled as unconditional. Only unresolved symbols and missing procedures refuse a job (`preprocess.py:16-18`).
10. **No JCL flavour is detected.** There is no token for JCL2, z/OS Chief, VSE, BS2000 or OS/400 anywhere in the repository (grep), and no built-in symbolics (`&SYSUID`, `&SYSDATE`, `&SYSTIME`) are modelled (grep) — those are reported unresolved (fail closed, `jcl_syntax.py:168-180`) rather than substituted; the two symbol regexes also differ (`jcl_syntax.py:13` caps names at 8 chars, `engine/jcl/preprocess.py:34` does not).
11. **The two REPLACING parsers disagree.** The engine applies COBOL-word operands and refuses quoted literals by name (`copybook_model.py:532-537,561-597`); discovery records pseudo-text pairs only — word and literal operands are dropped from `replacing_pairs` with **no** problem code, since `unsupported` is limited to `LEADING`/`TRAILING`/`PARTIAL`/unpaired pseudo-text (`cobol_structure.py:171-186`).
12. **Library order is a heuristic, not the JCL's.** Same-directory-then-shortest (`resolve.py:426-430`) vs root-then-sorted (`copybook_resolver.py:78-100`); JCLLIB/SYSLIB/PROCLIB order is recorded (`scan_jcl.py:125-127`) but never applied — already filed in `docs/discovery/KNOWLEDGE_GRAPH_AUDIT.md:22` and `docs/discovery/LAYER_AUDIT.md:27,32`.
13. **Signal matching is position-blind.** `_dialect` accepts any word token equal to a signal (`scan_cobol.py:273-281`), so a data item named `SCREEN`, `JSON` or `XML` counts as vendor evidence and can win the ranking (`runtime_deps.py:167-178`); no false-positive fixture exists.

## Target architecture (extend current code; no new parser, no LLM)
* **`DialectProfile` — one frozen, deterministic record per file** produced by discovery from facts only: `dialect` + `confidence`, `reference_format` (`fixed|free|variable|mixed` with switch line numbers), `compiler_options` (from `CBL`/`PROCESS`/`$SET`), `directive_state` (evaluated `>>IF` for the computable subset, else named), `library_order`, `unsupported` (construct names), `oracle` (`gnucobol-3.1.2`, selected `-std`, format flag). Canonical JSON, `profile_id = sha256` of bytes; added to `report["dialects"]` (`runtime_deps.py:151-187`) and to the evidence next to `oracle_id` (`engine/domain/identities.py:101`), never replacing existing fields.
* **One reference-format reader.** `cobol_text.logical_lines` is the superset (cards, `$SET`, mid-file switch, debug lines); `engine/transformation/source_format.py` becomes a thin consumer of it so parser, oracle and discovery read identical bytes — behaviour guarded by byte-identical generated output (the `docs/audits/CHANGE_LEDGER.md` hash method).
* **Fail closed by name.** `DIALECT_UNDETERMINED`, `REFERENCE_FORMAT_MIXED_UNSUPPORTED`, `REFERENCE_FORMAT_VARIABLE_UNSUPPORTED`, `COMPILER_CARD_UNHANDLED`, `CONDITIONAL_COMPILATION_UNEVALUATED`, `OO_COBOL_UNSUPPORTED`, `SCREEN_SECTION_UNSUPPORTED`, `JCL_FLAVOUR_UNRECOGNISED` — each an `UNSUPPORTED_*` refusal with `file:line`, never a silent default. Advisory lanes (the syntax check) may keep a labelled approximation exactly as today (`compilers.py:396-397`).
* **One REPLACING module and one library-order authority** shared by `copybook_model._parse_replacing_clause`, `cobol_structure.parse_replacing` and the resolvers; agreement is enforced by fixture parity, not by documentation.
* **Oracle std is data, not a constant:** `-std=` and the format flag come from the profile and are recorded with the identity; verdict scope text stays as it is (`contracts/ORACLE_CONTRACT.md:36`).

## Phases
* **P1 (record, no behaviour change):** `DialectProfile` + `profile_id`, fed from `dialect_report`, `logical_lines` and `compilers._STD_BY_DIALECT`; surfaced in `report["dialects"]` and the API; determinism and byte-identical discovery output tests.
* **P2 (single reader):** engine delegates reference-format reading to `cobol_text`; cards, `$SET` and mid-file switches handled or refused by name; oracle evidence gains `profile_id`, `-std` and format flag (advisory lane first).
* **P3 (shared language modules):** one REPLACING parser and one library-order authority applied by discovery *and* engine; `>>IF`/`>>DEFINE` evaluated for literal defines, otherwise refused; `compile-step` compiler names feed the profile.
* **P4 (engine consumes the profile):** generation refuses named dialect-unsupported constructs before parsing (OO, `SCREEN SECTION`, `VARIABLE`, unevaluated `>>IF`); `docs/CAPABILITY_MATRIX.md`, `docs/KNOWN_ISSUES.md`, `docs/audits/CHANGE_LEDGER.md` updated; import-lint rule that no module re-detects format or dialect on its own.

## Acceptance criteria
1. The same corpus yields a byte-identical profile JSON and `profile_id` regardless of file order; a second run differs only when source bytes differ.
2. Mixed-format fixture (fixed header, `>>SOURCE FORMAT FREE` mid-file): discovery and engine token streams agree at every `(line, column)`; if the check lane cannot flag it per segment, the verdict is a named `NOT_ATTEMPTED_REFERENCE_FORMAT`, never `COMPILE_ERRORS`.
3. `$SET SOURCEFORMAT"FREE"` fixture parses identically on both sides; a `VARIABLE` file yields `REFERENCE_FORMAT_VARIABLE_UNSUPPORTED`, never a silent fixed read.
4. `CBL ARITH(EXTEND),DYNAM` and `++INCLUDE X` fixtures: cards become facts on the discovery side and never appear as COBOL statements in engine diagnostics or IR.
5. `>>IF/>>ELSE` fixture: either both branches are gated by a documented `>>DEFINE` set or the program is refused `CONDITIONAL_COMPILATION_UNEVALUATED`; dead-branch statements never enter the graph or the IR.
6. `CLASS-ID` fixture is refused by name (`OO_COBOL_UNSUPPORTED`), never transformed into a Java type named `UNKNOWN`; `SCREEN SECTION` fixture is refused (`SCREEN_SECTION_UNSUPPORTED`) or documented as a bounded subset with a proof.
7. Dialect: a fixture whose JCL invokes `ELAXF` changes `primary` to `microfocus`; a fixture whose only signal is a data item named `JSON` stays `undetermined`.
8. REPLACING parity: identical supported/refused forms on both sides; a literal-operand `COPY` produces the same named refusal code from discovery and from generation; every untouched fixture's generated project stays byte-identical (hash before/after).
9. Library-order fixture: same-named copybooks resolve in JCLLIB/SYSLIB order, the loser is listed in `candidates`, and engine and discovery pick the same file.
10. Oracle evidence records `std`, format flag and `profile_id` beside `oracle_id`; `tests/discovery/test_compilers_applications.py:430-432` still passes (no GnuCOBOL result is ever phrased as a customer-compiler verdict).
11. Every new refusal code has a fixture and a `docs/CAPABILITY_MATRIX.md` row; the hermetic suite and the generated-output hashes of all corpus fixtures are unchanged by P1 and P2.

## Out of scope / explicitly unsupported
* Proprietary IBM and Micro Focus compilers, CICS/Db2/IMS/MQ translators and Language Environment: never installed, called or emulated (`docs/discovery/COMPILER_AND_APPLICATION_DISCOVERY.md:29`, `compilers.py:60-77`).
* `cobc -std=ibm` is an approximation, not IBM Enterprise COBOL (`compilers.py:66-68`); a GnuCOBOL syntax pass is never a verdict from the customer's compiler (`compilers.py:396-397`, `DISCOVERY.md:97`).
* z/OS, JES and JCL runtime equivalence, MVS-class execution (`contracts/ORACLE_CONTRACT.md:36,143-145`, `engine/jcl/__init__.py:18`).
* Non-z/OS JCL flavours (JCL2, z/OS Chief, VSE, BS2000, OS/400) and USS JCL dialects beyond `DD PATH`: not recognised, not promised (`scan_jcl.py:96-134`).
* Evaluating JCL `IF/ELSE` and `COND=(rc,op)` (`docs/specs/JCL_INTEGRATION_CONTRACT.md:142`): recorded, never evaluated.
* EBCDIC/code-page semantics beyond the documented narrow cases (`engine/vsam/collation.py:4`) and non-ASCII `PIC X` data (`docs/KNOWN_ISSUES.md:17-20`).
* Rewriting any parser now: this document changes no code; the shared-module work belongs to P2 of `docs/discovery/KNOWLEDGE_GRAPH_AUDIT.md` plus the phases above.
