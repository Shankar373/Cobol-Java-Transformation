# Layer 4 residual disposition (audit after Phase 0, ADR-0013)

Scope: every Layer 4 prerequisite the closure record in `DIALECT_PARSER_FRONTEND_AUDIT.md` left open. Each item is
classified FIXED, UNSUPPORTED-WITH-EXPLICIT-REFUSAL (already refused by name today), or OWNER-DECISION (needs a
documented acceptance; a recommendation and the evidence that would justify each option are given). Nothing here
applies a fix that changes generated output: `python tools/generation_hashes.py --check docs/audits/generation_hashes.json`
prints `identical: 55 apps x 2 runtimes = 110 builds (92 generated, 18 refused)` with every change in this audit applied.
Behaviour was observed by running small scripts and the focused tests listed below; GnuCOBOL itself was not run (no
Docker), so statements about what GnuCOBOL does are marked as reasoned, not observed.

## Changes made in this audit

* `enterprise/discovery/cobol_text.py`: after folding a continuation line, strip a `*>` comment that lies outside every
  literal (bug 3c). Discovery output changes only for sources with such a comment; engine output does not.
* `tests/discovery/test_profile_engine_refusal_agreement.py` (new): profile versus engine refusal agreement,
  mutation-sensitive, plus the two consumption pins and the findings of item 2.
* `tests/transformation/test_positions_residuals_layer4.py` (new): residual position cases (agreeing cases are ordinary
  tests; divergences are strict xfails that go red when a face changes).
* No refusal code was added: each candidate failed rule (a), (b) or (c), or needs a matrix row this audit may not write.
